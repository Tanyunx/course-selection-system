# 现场演示操作卡

> 一张纸说清「下次课现场生成选课系统」该怎么走。按场景选一条路线，命令可直接复制。

---

## 先决定走哪条路线

| 路线 | 前提 | 启动耗时 | 适合场景 |
|:--|:--|:--:|:--|
| **A · 单文件版** | 只要一个浏览器 | **0 秒**（双击） | 教室网络不稳、环境没配好、只想演示功能 |
| **B · 完整链路** | 本机装了 JDK 21 + PostgreSQL | 约 30 秒 | 要展示「前后端分离 + 真实数据库 + 事务」 |
| **C · Linux 学生机** | 一台 Ubuntu（含云服务器） | 首次约 5 分钟 | 满足「学生机用 Linux」这条要求 |

**稳的做法**：先走 A 兜底（保证一定能演示），再按 B/C 展示工程完整度。

---

## 路线 A · 单文件版（零依赖，最保险）

**操作**：双击打开工程根目录的 `选课系统-单文件版.html`。

- 331.7 KB 单个 HTML，**CSS 与 JS 全部内联**，无任何外部请求
- 业务规则引擎、种子数据都在文件里，**不连数据库、不连后端、不需要网络**
- 数据存在浏览器内存中，刷新即恢复初始状态；页面底部有「重置演示数据」按钮
- 已实测：单文件版界面 **51/51**、分发包一致性 **20/20**（含真实模拟填表登录、四角色全页面渲染、菜单权限矩阵）

> 可直接投影演示，也可以发给同学各自打开看。

## 路线 B · 完整链路（本机，Windows）

三条命令，各开一个终端窗口：

```bash
# ① 后端（Spring Boot + PostgreSQL）——首次运行加 --init 会重建演示库
bash tools/run-backend.sh --init

# ② 前端（静态托管 + /api 反向代理到 3000）
node tools/serve-frontend.js

# ③ 浏览器打开
#    http://127.0.0.1:5500
```

如果还没建过库，先跑一次建库脚本：

```bash
bash tools/pg-setup.sh    # 生成随机口令写入 backend/.env，建角色、建库、导 18 张表
```

忘了 jar 在哪、或者代码改过要重新打包：

```bash
bash tools/build-backend.sh    # 走阿里云镜像，打包出 backend/target/course-selection-backend.jar
```

**建议演示前先重建一次库**，回到干净的初始数据（16 门开课、8 学生、无测试残留）：

```bash
bash tools/run-backend.sh --init
```

## 路线 C · Linux 学生机 / 云服务器

```bash
git clone https://github.com/Tanyunx/course-selection-system.git
cd course-selection-system

# 一键部署：装 JDK、Maven、PostgreSQL，建库导数据，打包，systemd 托管，Nginx 反代
sudo bash deploy.sh

# 有域名想顺带开 HTTPS：
sudo bash deploy.sh --domain 你的域名 --email 你的邮箱
```

在 Windows 上不想装 Maven 时，工程自带 Maven Wrapper（`backend/mvnw`），**无需预装 Maven**：

```bash
cd backend && ./mvnw -DskipTests clean package
```

> `run-backend.sh` 定位 java 的顺序是：`JAVA_HOME` → `PATH` → Windows 常见路径，所以同一份脚本在 Windows 和 Ubuntu 上都能直接跑。

## 建议的演示动线（约 8 分钟）

1. **学生选课** — 用 `2024001` 选一门课，展示余量实时变化
2. **冲突检测** — 再选一门时间重叠的课，展示三维判定（星期 + 节次区间 + 单双周）的拦截提示
3. **先修校验** — 换 `2025001` 登录，选需要先修的课，展示被拦 + 具体原因
4. **候补递补** — 选一门已满的课进候补队列；再用 `academic` 退掉一个名额，回来看是否自动递补
5. **并发防超卖**（最有说服力）— 用教务端把某班容量改成 1，两个浏览器同时抢，第二个被挡
6. **操作留痕** — 用 `sysadmin` 打开审计日志，前面所有动作都在里面

## 关于「注意选课数据来源」怎么讲

这句话是要求你**说清楚数据从哪来**。三层结构：

```
前端（frontend/）
   ↓ fetch /api/...        ← 前端不持有任何业务数据，只发请求
后端（backend/，Spring Boot）
   ↓ JDBC + 事务            ← 业务规则、事务边界、并发控制都在这一层
数据库（PostgreSQL，18 张表）  ← 唯一数据源；约束、外键、触发器、行级锁在这一层
```

三个关键点：

1. **种子数据从哪来**：`backend/src/main/resources/db/seed-pg.sql`，启动时由 `DbInitializer` 导入（仅在 `--init` 时执行）。内容是模拟数据，但**存在真实的 PostgreSQL 里**，受真实约束管理。
2. **阶段一的 mock 在哪**：`frontend/mock/`（6 个文件，40 KB），可以脱离后端跑通全流程；当前**已不在运行链路上**。对照作业里「开始时数据可以先用 mock」这一条，正好体现两个阶段的演进。
3. **怎么证明不是 mock**：查 `t_audit_log`。每次登录与关键操作都会落库——mock 在浏览器里就把请求吃掉了，数据库不会留下痕迹。

## 排障速查

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 页面能开但列表空白 | 后端没起，或端口不对 | `curl http://127.0.0.1:3000/api/health`，应返回 `"status":"UP"` |
| 登录提示失败 | 数据库没建 / 演示库没导 | `bash tools/pg-setup.sh` 后 `bash tools/run-backend.sh --init` |
| `SERVER__PORT` 之类端口被劫持 | 环境变量宽松绑定 | 脚本已用**命令行参数**下发端口（优先级最高），直接跑脚本即可 |
| `./mvnw` 报 `\r: command not found` | 换行符变成了 CRLF | `.gitattributes` 已约束 `mvnw` 为 LF；若已污染：`git rm --cached -r . && git checkout .` |
| 前端在 5500 打开但接口 404 | 没经过代理 | 用 `node tools/serve-frontend.js` 托管，它会同时反代 `/api` |

# 3. 六套测试全绿吗（需要后端已在 3000 运行）

node tests/acceptance.js && node tests/concurrency.js && \
