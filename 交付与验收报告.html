3核心业务规则实现要点

规则实现方式
防超卖条件更新 UPDATE t_course_offering SET enrolled = enrolled + 1 WHERE id = ? AND enrolled < capacity AND status <> 0，影响行数为 0 即判定已满
时间冲突检测纯 SQL 自连接：星期相同 + 节次区间相交 + 单双周不互斥（全周与任一周次视为冲突）
选课校验顺序鉴权 → 幂等 → 批次(2005) → 重复(2006/2007) → 占名额(2001) → 冲突(2002) → 学分(2003) → 先修(2004) → 落库；任一步失败整体回滚，名额自动归还
换课「先占后放」单一事务，目标课程无余量直接返回 2009 且原课程不受影响
候补递补退课后按队列触发递补，递补时二次校验冲突与学分；失败则标记失效并顺延给下一位；超时未确认自动过期
幂等requestId 缓存已处理响应（默认 5 分钟），重复提交返回首次结果
防刷限速60 秒内 10 次写请求触发 9001，20 次要求验证码；读接口不受影响
权限控制四类角色 RBAC，越权访问返回 1003 并写入审计日志

5本轮修复记录

前端集成验证与数据一致性核查共发现并修复 7 个缺陷。

位置级别问题与修复
选课规则引擎
ruleService.js		 严重 事务内嵌套申请连接导致连接池死锁。事务中调用的规则函数仍从连接池取连接，池上限被占满后事务内再申请连接会永久等待，并与其他请求形成环形等待，验收测试挂起 4 分钟。修复：引入统一的 runner(conn) 执行器，全部规则函数支持传入事务连接。修复后验收测试耗时降至 8 秒。
演示数据
db/seed.sql		 中 种子数据存在真实排课冲突。学生 2024001 的数据结构与高等数学都被排在周一 1-2 节，导致学生课表页出现「检测到课表内存在时间冲突」提示。修复：将该开课的首次时段调整为周二 1-2 节（教师与教室该时段均空闲），全量扫描后冲突归零，同时保留用于演示冲突状态标签的课程。
教务端课程目录
views/admin.js		 严重 访问了页面中不存在的元素。渲染函数中残留一行操作「新增课程」弹窗元素的代码，该元素在页面骨架中并不存在，导致整个课程目录页报错打不开。修复：移除该行及随之失效的变量。
前端框架
app.js · ui.js		 中 退出登录后残留路由触发空引用；弹窗关闭依赖事件冒泡。退出登录后残留的地址变化会让菜单渲染读取到空身份对象而抛异常（已加空值保护）；弹窗关闭按钮原依赖事件委托，改为直接绑定以提升健壮性。
登录页验证码
app.js		 严重 验证码题目永远无法显示。脚本引用了不存在的元素 id（#captcha-question，实际按钮 id 为 captcha-refresh），加载题目时抛出未捕获异常。修复：统一引用真实 id 并加元素存在性保护；登录页初始化时预取验证码，需要作答时题目已就绪。
全局样式
app.css · index.html		 严重 hidden 属性被类选择器覆盖而失效。登录页、应用框架、验证码输入区三类容器都设置了 display 的类规则，优先级高于浏览器对 hidden 属性的默认样式，导致登录页与应用框架同时渲染、验证码区在未触发时也一直可见。修复：新增全局 [hidden] { display: none !important; } 兜底规则，并经真实浏览器（无头 Edge）截图复核。
节次时间表
ui.js · utils/period.js		 中 节次时间与学校《课时表》不符。原实现采用 8 节 45 分钟制（08:00-08:45 起、19:00 后还有 9~12 节），与学校统一的 13 节 40 分钟制（上午 1~5 节、下午 6~10 节、晚上 11~13 节，大节划分一 1-2 / 二 3-5 / 三 6-7 / 四 8-10 / 五 11-13）不一致。修复：前后端统一更换为课时表标准时间（新增 server/utils/period.js 与前端常量保持同源）；课表增加「时段」列并标注每节起止时间；选课规则页新增完整课时表；排课编辑器节次上限改为 13 并在选项中显示时间；教师端与教务端排课校验统一走 assertValidSchedules（教务端此前缺少节次合法性校验，一并补上）。
