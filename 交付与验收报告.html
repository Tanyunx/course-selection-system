三、核心要求：数据冲突在数据库控制、事务、考虑多人

这是本次作业的核心考点。设计上把"判断是否还有名额"与"名额自增"压缩进同一条 SQL， 依靠 PostgreSQL 的行锁保证原子性，不依赖任何应用层锁，也不引入 Redis：

UPDATE t_course_offering
   SET enrolled = enrolled + 1
 WHERE id = ? AND enrolled < capacity AND status <> 0

受影响行数为 0 即代表"没抢到"，返回 2001 已满； 后续的冲突 / 学分 / 先修校验若失败，整个事务回滚，已占名额自动归还。 同时用唯一约束 uk_student_offering 作为最后防线。

其他并发控制点

  • 换课：单一事务"先占后放"——预占目标名额 → 校验（冲突检测排除即将释放的原课程）→ 释放原名额 → 重建记录；任一步失败返回 2009 且原课程完全不变。
  • 候补排位号：先 SELECT id FROM t_course_offering WHERE id = ? FOR UPDATE 锁住开课行，把同一门课的入队串行化，再取 MAX(queue_no)+1，避免两人拿到同一排位。
  • 候补递补二次校验：排队期间学生课表可能已变，递补时重新执行完整校验；不通过则置为已失效、发通知并顺延下一名（实测 TC-11 覆盖）。

四、本轮修复的缺陷（移植过程中真实踩到）

1. 平台环境变量劫持监听端口

宿主环境存在平台预设的 SERVER__PORT，Spring 的宽松绑定会把它解析成 server.port， 导致明明配置是 3000、Tomcat 却起在别的端口并冲突。 修复：改为用命令行参数下发 --server.port / --server.address （命令行优先级高于环境变量与配置文件），从根上杜绝。

2. Java 文本块剥离行尾空白 → SQL 拼接错误

文本块 """ 会剥掉每行行尾空白，于是 WHERE """ + where 拼成了 WHEREo.term_id， 数据库报 syntax error at or near "WHEREo"。共 3 处同源缺陷。 修复：改用 \s 转义（文本块中唯一不会被剥离的空白写法）。

3. 占位符多于参数时被静默补 null

为说明上面这件事，我在 SQL 注释里写了一个带 ? 的示例， 结果 Db.prepare() 把注释里的问号也当成占位符， 而它当时遇到"占位符多于参数"只是默默补一个 null， 最终由 PostgreSQL 抛出"栏位索引超过许可范围：4，栏位数：3"，排查成本极高。 修复：注释里不再出现裸问号；Db.prepare() 在参数不匹配时立即抛异常并打印完整 SQL。

4. PostgreSQL 不允许 FOR UPDATE 与聚合函数同用

SELECT COALESCE(MAX(queue_no),0) ... FOR UPDATE 在 MySQL 下能跑， 在 PostgreSQL 下报 0A000 feature_not_supported；更麻烦的是 HikariCP 会把该连接标记为 broken， 导致事务回滚也失败，前端只看到一个笼统的 9002 系统繁忙。 修复：先锁开课行再取 MAX，语义等价且是 PG 允许的写法。

5. 迁移相关：整数除法、IN (?) 展开、insertId

  • PostgreSQL 整数相除会截断 → 利用率排序改为 enrolled::numeric / NULLIF(capacity,0)。
  • PostgreSQL JDBC 不会像 MySQL 驱动那样自动展开数组参数 → 在 Db.prepare() 里把 IN (?) 展开为 IN (?,?,…)。
  • 没有 insertId → Db.insertReturningId() 自动补 RETURNING id。

6. 前端 API 基地址与测试自身的问题

  • 前端用同源相对路径 /api/…，前后端拆分后本地把前端跑在别的端口会打到前端自己。 修复：新增 apiBase() 支持 ?api= / window.__API_BASE__ 覆盖， 并补了零依赖的 tools/serve-frontend.js（静态托管 + /api 代理，本地也保持同源）。
  • tests/concurrency.js 自身有两处缺陷：只按"课程"维度挑候选，撞上种子数据里"同课同教师"的唯一约束； 以及用 offeringId 读教务端列表而实际字段是 offering_id。已修复。
  • tests/acceptance.js 仍在 require 已归档的 Node 后端配置 → 改为 pg + bcryptjs + 环境变量， 并在 sql() 助手里统一吸收 ?→$n、数组展开、RETURNING id、INTERVAL 四处语法差异。
